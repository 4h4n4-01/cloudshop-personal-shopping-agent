# CloudShop — an agentic clothes-shopping assistant

**CS 619 course project.** A shopper describes what they want in plain words. Four cooperating
agents turn that into a **checked shortlist** and an **approval-gated purchase**:

```
 Shopper ─► 1 Intake ─► 2 Stylist ─► 3 Verifier ─► 4 Checkout ─► Payment plugin
           (brief +     (tool use:    (code checks   (plan → human    (MockPay; swap in
            chips)        search,       + claim        approval → pay)   Stripe test mode)
                          stock)        grounding)
```

A custom web GUI lets the shopper move between agents (left sidebar); an **Agent activity** drawer
shows every LLM call, tool call, decision and human action — so the multi-agent system is never opaque.

## The course design ideas (graded)

The course asks for three; this project implements **four**, all user-facing:

| # | Course idea | Code | What the shopper sees | How it's evaluated |
|---|---|---|---|---|
| 1 | **Making intent expression easier** (Wk 1) | `app/agents/intake.py` | Free text → editable brief, each field tagged *you said / AI inferred / you edited*; gaps asked as clickable chips | E1: field accuracy, clarification recall |
| 2 | **Verifying AI output** (Wk 2) | `app/agents/verifier.py` | Every pick has a verdict badge + evidence checklist; claims checked vs. product data; Verify-tab matrix | E2: fault-injection recall, false-alarm rate, no-verifier ablation |
| 3 | **Human oversight & intervention** (Wk 4) | `app/agents/checkout.py` | Plan shown before any charge; approval bound to a plan hash; cart change voids it; spend cap override | E3: checkout safety invariants |
| 4 | **Agent memory / personalisation** (Wk 4) | `app/memory.py` | "Shopping as…" a returning customer pre-fills the brief from their history (tagged *remembered*) and biases picks ("in navy, a colour you've chosen before"); **collaborative filtering** promotes brief-matching items that *look-alike shoppers* chose; a "what we remember" panel you can edit / forget | E4: taste-match depth, avoided-attr leakage, collaborative coverage |

**Supporting architecture (not graded, kept user-inspectable):** tool use (Wk 3) in the Stylist;
multiple agents (Wk 6) with proposer ≠ checker and no LLM holding the payment tool. Full rationale and
design variations: [docs/DESIGN.md](docs/DESIGN.md). Proposal: [docs/PROPOSAL.md](docs/PROPOSAL.md).

## Data pipeline (bronze → silver → gold)

The product catalog is built by a Medallion pipeline, the same layering as the MLE assignment:

| Layer | What | Output |
|---|---|---|
| **Bronze** | Raw ingestion, copied verbatim (the CloudShop Marketplace source) | `data/datamart/bronze/` |
| **Silver** | One *conformed* clean table: type, enforce controlled vocab, drop out-of-scope rows | `data/datamart/silver/products.json` |
| **Gold** | Serving layer: combined catalog (+ derived `department`, `emoji`, `sizes_in_stock`, `in_stock`, `price_tier`), a per-size stock store, **and partitioned views by department × section** | `gold/catalog.json`, `gold/stock.json`, `gold/catalog/{clothing,shoes,bags}/{women,men,unisex}.json` |

```powershell
python main.py          # rebuild data/datamart/ from data/source/ (1,201 in → 1,201 gold products)
```

The app reads the **gold** catalog and rebuilds it automatically if missing, so this step is
optional locally and runs inside the Docker image at build time.

## Run it

**Python 3.10+**
```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env        # add ANTHROPIC_API_KEY, or leave empty for offline mock mode
uvicorn app.main:app --reload
```
**Docker**
```powershell
docker build -t cloudshop .
docker run --rm -p 8000:8000 --env-file .env cloudshop
```
Then open http://127.0.0.1:8000.

**Modes.** With `ANTHROPIC_API_KEY` set, agents use Claude; otherwise they fall back to deterministic
offline agents (free, reproducible — good for UI work, demos and the evaluation baseline). Force with
`LLM_MODE=claude|mock`.

**Catalog.** The **demo catalog** (1,201 synthetic products across 20 categories and 12 synthetic
retailers, offline) is what the evaluation and user study use. Each product carries commerce
attributes (fabric composition, care, origin, rating, returns, sale price, badges, free shipping) and
**fashion attributes** (silhouette/style — peplum, wrap, A-line, bodycon, chelsea… — plus sleeve
length, neckline, pattern, fit, hem length, rise, heel height — assigned per category). It's a **licence-free prototype**: products show an **emoji tile** for the category instead
of a copyrighted photo, so the whole design can be demoed and swapped for licensed live feeds later.
Checkout runs on **MockPay** (moves no real money; test cards `pm_card_visa`, `pm_card_declined`,
`pm_card_insufficient`).

**Why a synthetic storefront?** CloudShop is an **AI wrapper that sits on top of a shopping backend**.
The CloudShop Marketplace *is* that backend: a licence-free replica of a real online store. In a
production deployment it would be replaced by a real retailer's product feed once licensing and brand
agreements are signed — the four agents read one normalised product shape, so that swap wouldn't touch
them. See [docs/DESIGN.md](docs/DESIGN.md#data-source).

**Backend catalog viewer — two ways:**
- **Standalone (no server):** the pipeline writes a self-contained
  **`data/datamart/gold/catalog_viewer.html`** with the data embedded — just open the file in any
  browser. Hand this to anyone (e.g. a reviewer) who wants to inspect the catalogue without running
  anything.
- **Live:** open **http://127.0.0.1:8000/admin** (needs the server running) — the *same* page, but
  it fetches live from `GET /api/catalog/all`.

Both share one template ([pipeline/catalog_viewer_template.html](pipeline/catalog_viewer_template.html))
and offer ~20 controls: search, department, section, category, **colour** (multi, with swatches),
silhouette/style, pattern, sleeve, neckline, fit, hem length, rise, heel height, **occasion** (multi),
**material** (multi), store, price sliders, min-rating, and in-stock / on-sale / free-shipping / badge
toggles, plus sort. Colour / category / occasion / material are multi-select.

## Test and evaluate

```powershell
python -m pytest -q                                 # end-to-end API flow (mock mode)
python -m eval.run_eval                              # E1 intake · E2 verifier · E3 oversight (mock)
$env:LLM_MODE="claude"; python -m eval.run_eval      # same, with Claude (uses API credits)
```

Evaluation design, held-out set, ablations and the user-study protocol: [docs/EVALUATION.md](docs/EVALUATION.md).
